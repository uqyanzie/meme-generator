# TKT-109: Quota Bypass via Concurrent Requests (Race Condition)

- **Execution Order:** 9
- **Layer:** Backend
- **Status:** Open
- **Related Tickets:** [TKT-101](../TKT-101/TKT-101.md), [TKT-107](../TKT-107/TKT-107.md)

---

## Summary

Users can exceed their subscription plan's meme generation quota by submitting concurrent requests across multiple browser tabs.

## Reported Behavior

A user with a 20-meme quota opened six tabs simultaneously and was able to generate 25 memes before the system rejected further requests.

## Expected Behavior

Quota verification and meme creation must be serialized/atomic per user so concurrent requests cannot bypass the configured `max_memes` limit, while still allowing a user's final valid meme (e.g., meme #10 of 10) to complete its `result-upload` and `complete` steps without being falsely blocked.

## Potential Impact

Quota enforcement bypass, unfair resource usage, and storage/compute cost abuse.

---

## Initial Codebase Touchpoints

- `api/internal/server/v1/v1.go` (`subscriptionGate.CanCreate` runs `Status` / `SELECT COUNT(*)` outside any transaction).
- `api/internal/modules/meme/service.go`:
  - `PrepareUpload` checks `s.gate.CanCreate` then separately calls `s.repo.Create` (TOCTOU race window).
  - `ResultUpload` and `Complete` also call `s.gate.CanCreate` — subtle off-by-one risk on the final allowed meme after `PrepareUpload` inserts the row!
- `api/internal/modules/meme/repository.go` & `api/internal/modules/subscription/repository.go`.

---

## Pending Decisions (Discuss Before Implementation)

- [ ] **Concurrency control mechanism:** Choose locking approach inside a PostgreSQL transaction during `PrepareUpload`:
  1. `SELECT ... FROM subscriptions WHERE user_id = $1 AND status = 'active' AND ends_at > now() ... FOR UPDATE` (locks the active subscription row, counts memes in the same tx, inserts meme row atomically), OR
  2. Transaction-scoped advisory lock (`pg_advisory_xact_lock`) keyed by `userID`.
- [ ] **Final-meme (`ResultUpload` / `Complete`) gate check:** Confirm separating "can create new meme (active sub + quota remaining)" on `PrepareUpload` from "has active subscription (no quota re-check for an already-reserved meme row)" on `ResultUpload` and `Complete`.
