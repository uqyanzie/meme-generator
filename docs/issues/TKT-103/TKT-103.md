# TKT-103: Broken Logout Flow and Infinite Redirect Loop

- **Execution Order:** 1
- **Layer:** Backend + Frontend
- **Status:** Open
- **Related Tickets:** Unblocks clean multi-user reproduction for [TKT-102](../TKT-102/TKT-102.md) and [TKT-107](../TKT-107/TKT-107.md)

---

## Summary

Logging out fails to clear the session properly, resulting in an infinite redirect loop between the login page and the home page.

## Reported Behavior

After clicking "Logout" (Keluar), the action appears to succeed. However, navigating to the login page immediately redirects the user to the home page, which in turn redirects back to the login page repeatedly.

## Expected Behavior

Logging out must invalidate/clear the user's authentication cookies and session state so that subsequent navigation to `/login` renders the login form cleanly without redirecting in a loop.

## Potential Impact

Users are locked out of the application or trapped in an infinite redirect loop after logging out.

---

## Initial Codebase Touchpoints

- `api/internal/modules/auth/handler.go` (`clearAuthCookies` sets `Path: "/api/v1/auth"` instead of `"/"`, ignoring `cookie.Clear`).
- `api/internal/platform/cookie/cookie.go` (`cookie.Set` uses `HttpOnly: false` and `Path: "/"`; `cookie.Clear` already exists with `Path: "/"`).
- `web/src/app/login/page.tsx` (redirects to `/` whenever `document.cookie.includes("meme_access_token")`).
- `web/src/app/page.tsx` (redirects to `/login` when `!me.isLoading && !me.data`).
- `web/src/lib/auth.ts` (`useLogout` clears React Query cache and navigates to `/`).

## Pending Decisions (Discuss Before Implementation)

- [ ] **Cookie `HttpOnly` flag:** Should we change `cookie.Set` in `api/internal/platform/cookie/cookie.go` from `HttpOnly: false` to `HttpOnly: true` (preventing XSS token theft) since `/login` should rely on verified `useMe()` instead of `document.cookie`?
- [ ] **Home page (`/`) access policy:** Should `/` remain a public landing page (removing the forced redirect to `/login` for unauthenticated visitors), or stay protected while `/login` only redirects when `useMe()` confirms a valid session?
- [ ] **Access token invalidation on logout:** Currently `Logout` revokes the refresh token in Redis, while the short-lived JWT access token remains cryptographically valid until TTL if copied. Should we keep cookie clearing + refresh revocation (minimal fix) or also blacklist/revoke active access tokens in Redis?
