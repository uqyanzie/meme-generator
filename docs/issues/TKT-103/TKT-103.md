# TKT-103: Broken Logout Flow and Infinite Redirect Loop

- **Execution Order:** 1
- **Layer:** Backend + Frontend
- **Status:** Resolved
- **Related Tickets:** Unblocks clean multi-user reproduction for [TKT-102](../TKT-102/TKT-102.md) and [TKT-107](../TKT-107/TKT-107.md)

---

## Summary

Logging out fails to clear the session properly, resulting in an infinite redirect loop between the login page and the home page.

## Reported Behavior

After clicking "Logout" (Keluar), the action appears to succeed. However, navigating to the login page immediately redirects the user to the home page, which in turn redirects back to the login page repeatedly.

## Expected Behavior

Logging out must invalidate/clear the user's authentication cookies and session state so that subsequent navigation to `/login` renders the login form cleanly without redirecting in a loop.

## Potential Impact

Users are locked out of the application or trapped in an infinite redirect loop after logging out.

---

## Initial Codebase Touchpoints

- `api/internal/modules/auth/handler.go` (`clearAuthCookies` sets `Path: "/api/v1/auth"` instead of `"/"`, ignoring `cookie.Clear`).
- `api/internal/modules/auth/mount.go` (`POST /api/v1/auth/logout` is currently blocked by `authMW`, preventing expired sessions from clearing stale cookies).
- `api/internal/platform/cookie/cookie.go` (`cookie.Set` uses `HttpOnly: false` and `Path: "/"`; `cookie.Clear` already exists with `Path: "/"`).
- `api/internal/platform/token/jwt.go` & `api/internal/middleware/auth.go` (add `jti` claim + Redis denylist check in `VerifyAccess(ctx, raw)`).
- `web/src/app/login/page.tsx` & `web/src/app/register/page.tsx` (both redirect to `/` whenever `document.cookie.includes("meme_access_token")`).
- `web/src/app/page.tsx` (redirects to `/login` when `!me.isLoading && !me.data`).
- `web/src/lib/auth.ts` (`useLogout` clears React Query cache and navigates to `/`; `useRegister` does not invalidate `["me"]` on success).

---

## Decisions (Finalized)

- [x] **Cookie `HttpOnly` flag:** Change `cookie.Set` in `api/internal/platform/cookie/cookie.go` from `HttpOnly: false` to `HttpOnly: true`.
- [x] **Home page (`/`) access policy:** Keep `/` as a public landing page by removing its forced redirect to `/login`; existing navbar **Masuk / Daftar** buttons in `SiteHeader` are sufficient.
- [x] **Access token invalidation on logout:** Use **Option A (`jti` denylist)** — include a unique `jti` (`RegisteredClaims.ID`) in access tokens; on logout, revoke the refresh token in Redis and store `auth:revoked:access:<jti>` in Redis with TTL equal to the token's remaining lifetime; verify against this denylist in `VerifyAccess(ctx, raw)`.
- [x] **Auth pages (`/login` & `/register`) redirect guard:** Replace `document.cookie.includes("meme_access_token")` in **both** `login/page.tsx` and `register/page.tsx` with verified `useMe()` state (guarded against clashing with post-submit navigation to `/studio` / `/pricing`), and invalidate `["me"]` in `useRegister`.
- [x] **Logout resilience (best UX):** Make `POST /api/v1/auth/logout` idempotent/best-effort — extract and revoke access token (`jti`) and/or refresh token in Redis whenever valid tokens are present, and **always** clear both auth cookies with `Path: "/"` and return `200 OK` so users with expired sessions are never stuck unable to log out. Pair with `onSettled` cleanup in `useLogout`.
