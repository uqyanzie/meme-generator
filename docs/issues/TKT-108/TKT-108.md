# TKT-108: Arbitrary / Malicious File Uploads in S3 Storage

- **Execution Order:** 8
- **Layer:** Backend + Frontend
- **Status:** Resolved
- **Related Tickets:** [TKT-107](../TKT-107/TKT-107.md), [TKT-109](../TKT-109/TKT-109.md)

---

## Summary

Unrelated, oversized, and potentially malicious files (e.g., `GTA.V.Full.Installer.zip` at 90 GB, `.html`, and `.exe` files) were uploaded and stored in the S3 bucket.

## Reported Behavior

A storage audit revealed large non-image files and executable/HTML files stored in the application's S3 bucket.

## Expected Behavior

Upload preparation and storage endpoints must strictly validate allowed image file extensions, MIME content types, and maximum file size limits, rejecting disallowed types or oversized payloads before issuing upload capability (and enforcing constraints at upload time).

## Potential Impact

Severe storage cost abuse, malware/phishing/stored-XSS hosting via public S3 web endpoint, and security compliance risk.

---

## Initial Codebase Touchpoints

- `api/internal/modules/meme/service.go`:
  - `PrepareUpload` never calls `allowedExt(ext)` (which is defined in the same file).
  - Trusts client-supplied `contentType` raw without allowlist or extension-to-MIME matching.
  - Presigned `PutObjectInput` does not enforce `ContentLength` / size limit.
  - Check `ResultUpload` as well for size limits.
- `api/internal/modules/meme/handler.go` (`prepareUploadDTO`).
- `web/src/lib/queries.ts` & `web/src/app/studio/page.tsx` (`usePrepareUpload` currently only sends `{ title, filename }`, omitting `contentType` and file size, and relies only on HTML `accept="image/*"`).

---

## Pending Decisions (Discuss Before Implementation)

- [x] **Upload enforcement architecture:** **Signed Presigned PUT (`ContentLength` + `ContentType`)** — keep the direct-to-S3 presigned PUT architecture; client sends `fileSize` + `contentType` + `filename` to `POST /api/v1/memes/upload` (and `fileSize` to `POST /api/v1/memes/{id}/result-upload`); backend validates `allowedExt`, MIME allowlist + extension-to-MIME consistency, and `0 < fileSize <= maxUploadBytes`, then signs both `ContentLength` and `ContentType` into the S3 presigned PUT URL (verifying Garage S3 enforces both).
- [x] **Maximum file size limit:** **5 MiB (`5 * 1024 * 1024` = 5,242,880 bytes)** for both base image uploads and rendered PNG result uploads.
