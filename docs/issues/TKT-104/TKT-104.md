# TKT-104: Stale Subscription State in Navbar and Packages Page Until Hard Refresh

- **Execution Order:** 3
- **Layer:** Frontend
- **Status:** Open
- **Related Tickets:** Paired with [TKT-102](../TKT-102/TKT-102.md)

---

## Summary

The UI does not reflect updated subscription and quota information after a successful purchase until a hard refresh (`Ctrl+Shift+R`) is performed.

## Reported Behavior

Following a successful package purchase, the package name in the top-right navbar remains empty and the quota on the Packages page remains at the previous value. Performing a hard refresh updates the UI to the correct state.

## Expected Behavior

Client-side state/cache must be invalidated and refetched cleanly upon payment confirmation (and after login or meme creation) so the navbar, Packages page, and Studio immediately display up-to-date subscription and quota data without a hard refresh.

## Potential Impact

Poor user experience and confusion regarding whether a payment succeeded.

---

## Initial Codebase Touchpoints

- `web/src/lib/queries.ts`:
  - `useSubscriptionStatus` sets `staleTime: Number.POSITIVE_INFINITY`.
  - `useCompleteMeme` only invalidates `["memes"]`, not `queryKeys.subscription`.
- `web/src/lib/auth.ts`:
  - `useLogin` only invalidates `["me"]`, not `queryKeys.subscription`.
- `web/src/components/site-header.tsx` & `web/src/app/pricing/page.tsx` (consumers of `useSubscriptionStatus`).
